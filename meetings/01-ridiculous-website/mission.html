Essential question

How can we turn a working starting point into a product page that feels unmistakably ours?

  1. Play the finished exampleStart with curiosity, not code.

    Use the preview on the right. Click Reveal a secret, read the review, and decide what feels intentionally ordinary about this page.

    DoClick the buttons and look at the page as a visitor.
    You should seeA secret message appear without leaving the page.
  2. Meet the three file jobsUse clues before you choose.

    You are not supposed to know this yet. Read the small clues, make a first guess, and then verify it by opening the real files in the next step.

    index.htmlWhat exists 
    <h1>Rock Royale</h1>
<img alt="...">

    Words, images, buttons, and structure.

    style.cssHow it looks 
    --product: #64748b;
--paper: #fff7ed;

    Colors, spacing, layout, and appearance.

    script.jsWhat it does 
    onClick("button", ...)

    Clicks, decisions, and visible responses.

    Which file holds the product title and image description?

    Which file holds the colors and layout rules?

    Which file contains the response to clicking Reveal a secret?

    Important: a guess is not a grade. You will prove it by opening the files and changing one line.

  3. Find the codeUse the Codespace tab for editing.

    Keep this Mission Control tab open. Switch to your Codespace tab, press Ctrl+P, and type the path below. On a Mac, use Cmd+P.

    meetings/ 01-ridiculous-website/ project/ index.html ← start here style.css script.js
    meetings/01-ridiculous-website/project/index.html

    Important: open the file in the Codespace editor, not in the browser preview. The preview is where you observe the result.

    Fresh-start file: use meetings/01-ridiculous-website/catch-up/index.html and the matching style.css.

  4. Make the guided remixChange one thing, save, and look again.

    Complete the baseline in order. Saving after each small change lets you connect the code to the visible result.

    EDIT 1 · Product name

    In index.html, replace the text inside the <h1>.

    <h1>Rock Royale</h1>
→ <h1>Emergency Invisible Umbrellas</h1>

    EDIT 2 · Description and alt text

    Change the description and describe the new image honestly in its alt text.

    <img ... alt="A dramatically lit invisible umbrella">

    EDIT 3 · Theme

    In style.css, change at least three values in the :root color variables.

    --product: #db2777;
--paper: #ecfeff;
--button: #0f766e;

    Look here: the title, description, image text, and color theme should all change in the preview. If one does not, change only that one thing again.

  5. Make it unmistakably yoursChoose a direction and build with your team.

    Complete the guided baseline first

    Choose one ridiculous product direction, then divide the work. The required result is small enough to finish today.

    Sell the impossible

    An emergency subscription for invisible umbrellas.

    Remix the ordinary

    A luxury store for rocks, pencils, or the school’s most boring object.

    Invent a problem

    A premium service that solves something nobody has.

    • Remix: change the product, image, price, review, button, and three colors.
    • Builder: copy one review card and turn it into a second review.
    • Boss Level: make the surprise button reveal a ridiculous fact or random testimonial.
  6. Test, explain, and broadcastMake your work understandable to another team.

    Ask a teammate or another team to use the page without coaching. Repair one confusing label, broken button, or visual problem.

    • Explain one HTML change and one CSS change.
    • Show the feature your team added.
    • Complete TEAM-LOG.md, AI-LOG.md if needed, and DEMO.md.
    • Commit with the message below, sync, verify it on GitHub, and stop the Codespace.
    Meeting 1: ridiculous website remix

    Demo sentence: “Our website exists because ____. The most ridiculous thing we intentionally built is ____.”

    Stuck ladder or curious about AI?
    1. Reread the current edit and compare the file with the preview.
    2. Ask the navigator or designer/tester to name what changed.
    3. Restore only the affected file from the starter if the page is damaged.

    After the baseline works, you may ask a peer, teacher, or optional AI adviser:

    Which file probably controls this color?
Do not rewrite the project. Give us one next step.

    Change one thing, test it, and record the decision in AI-LOG.md.
