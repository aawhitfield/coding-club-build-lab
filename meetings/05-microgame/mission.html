Essential question

What does a player need to understand and enjoy a tiny game in 30 seconds?

  1. Play the three basesChoose by the experience you want to create.

    Open a base from the panel, run it in Sprig, and play until you can explain how a player wins or loses.

    Collector

    Collect a star, then reach the goal.

    Avoider

    Reach the goal while avoiding danger.

    Push puzzle

    Push a box onto the goal.

    Quick choice

    Which base gives your team the most interesting starting idea? Name the input, feedback, and ending you noticed.

  2. Plan the 30-second loopAnswer the player’s first questions.

    Complete the planner before adding a mechanic. A good microgame answers these questions quickly:

    GoalWhat should I try to do?
    ControlWhat can I press or move?
    EndingHow do I know I won or lost?

    Which part tells the player whether the attempt is over?

    Use the selected base path in the Codespace tab as your backup. Run and save the active game in Sprig.

  3. Make the guided transformationIdentity first; mechanics second.

    Change the title/instructions, all visible art, and the map or level layout. Run after each edit.

    EDIT 1 · Identity

    Rename the game and rewrite the first instruction so a player knows the goal.

    “Collect the moon cheese before sunrise.”

    EDIT 2 · World

    Change the player, goal, and environment art. Keep the symbol keys intact.

    [goal, bitmap`...`]

    EDIT 3 · Level

    Change the map so the first move teaches the goal and the ending remains reachable.

    Move one obstacle or add one safe turn.

    Beginner finish line: a new player can play, understand the goal, and reach an ending. Mechanics from the recipe cards are optional level-ups.

  4. Run the player testUse evidence, not guesses, to revise.

    Complete the guided baseline first

    Ten-second test

    1. Give the game to a player without explaining the goal.
    2. After ten seconds, ask what they think they are trying to do.
    3. Ask whether they know when they have won or lost.
    4. Make one revision based on the answer.
    Remix

    Art, map, title, instructions, and ending.

    Builder

    Add one recipe mechanic: obstacle, level, sound, win, or lose.

    Boss

    Combine mechanics or add progressive difficulty.

  5. Save and explain the loopMake the player experience visible to your audience.

    Save in Sprig, copy the final code into the selected backup file, and commit with Meeting 5: microgame. Sync, verify, and stop the Codespace.

    Demo sentence: “Players try to ____ by using ____. We learned ____ from the ten-second test, so we changed ____.”

    Stuck ladder

    1. Run the last working version.
    2. Compare the map and one changed sprite with the base.
    3. Restore the base if the mechanic is no longer playable.
    4. Ask for one recipe-sized next step from a peer, teacher, or optional AI adviser.
