Essential question

How can a small, safe prototype help a specific person with a real moment of friction?

  1. Notice a small annoyanceStart with a person and a moment, not a giant app.

    Choose one fictional scenario or propose a harmless school moment. Then write: “For ____, who struggles with ____, we are building ____.”

    Study break

    A student needs a quick next-step suggestion.

    What to bring

    A student forgets materials for a club or event.

    Club finder

    A student wants to explore fictional clubs.

    Small / safe / useful check

    Which part of your idea can a user try in one minute without signing in or entering personal information?

  2. Find the prototype piecesLearn the screen jobs before editing.

    The starter already has screens, labels, buttons, and fictional choices. Your job is to change the experience without needing a database.

    index.htmlscreens
    h1 · p · button · select

    Content, labels, and structure.

    style.csstone
    background · border · spacing

    Visual identity and readability.

    script.jsflow
    goTo("tool-screen")

    Navigation between screens.

    Which file should you open to change the app title and button labels?

    meetings/06-school-problem/project/index.html
    meetings/06-school-problem/project/index.html

    In the Codespace tab, press Ctrl+P and open the path shown above.

  3. Build the guided prototypeMake one user path convincing.

    Change the title, audience text, labels, and colors. Keep the buttons working while you make the path yours.

    EDIT 1 · Audience

    Change the title and opening paragraph so a visitor knows who this helps.

    <h1>Helpful Helper</h1> → <h1>Club Compass</h1>

    EDIT 2 · User path

    Rename Start, the choice label, and the result button. Keep the path home → tool → result.

    Start → Find a suggestion → Show my route

    EDIT 3 · Visual signal

    Change at least three CSS values so the prototype has a clear visual identity.

    background · border · button color

    Prototype boundary: fictional data only; no accounts, tracking, official school claims, or real schedules.

  4. Let a user try itTest clarity before adding features.

    Complete the guided baseline first

    Walkthrough test

    1. Give the prototype to a teammate without explaining the idea.
    2. Ask them who they think it helps and what they would click first.
    3. Watch one path silently.
    4. Revise one label, screen, or visual cue.
    Remix

    Change content, audience, labels, and theme.

    Builder

    Add a screen or a safe sample input.

    Boss

    Begin a recommendation, calculator, sorter, or other algorithm for Meeting 7.

  5. State the problem and prototypeMake the audience part of the explanation.

    Commit with Meeting 6: school prototype, sync, verify the commit, and stop the Codespace.

    Demo sentence: “For ____, who struggles with ____, we built ____. A user can ____ without ____.”

    Stuck ladder

    1. Run the path from the home screen.
    2. Compare the visible label with the action you want.
    3. Ask the tester which moment was confusing.
    4. Restore one affected file, then ask a peer, teacher, or optional AI adviser.
